# libui-v29: bounded audit, no build module added

Decision: a supported drop-in dependency set was **not established within the
requested timebox**. This is not proof that a focused adaptation is impossible.
The full graph remains blocked on the undefined `libui-v29` module. No ELF
checks, visibility rules, source selections, or consumer binaries were changed.

Both original and generated BLA hwcomposer import sets are unchanged. Their
dependency lists differ only by the existing `libui.so` to `libui-v29.so` fixup.
The 17 imported UI symbols are `Region` operations plus `Rect::intersect` and
are all unversioned. Newer VNDK32/34 libraries also export those names; that
does not establish C++ object-layout compatibility or justify renaming them.

The original patch also references `vndk/v30/...` in its Blueprint while
carrying the binaries under `vndk/v29/...`; it is input evidence, not a directly
usable build description. Its `check_elf_files: false` was not adopted.

## First concrete integration obstacle

The unmodified candidate has 19 direct dependencies, including
`libhwbinder.so` and `libhidltransport.so`. All names are listed in the JSON.
In the selected LOS24 `system/libhwbinder/Android.bp`, `libhwbinder` has no
implementation sources and is visible only to its own subtree, `//vendor`,
and system filesystem partition modules. A vendor module under
`hardware/huawei` is outside those rules. A direct dependency is therefore not
a supported unchanged drop-in at this location.

The source provides a possible focused adaptation: `libhidlbase` now includes
the transport implementation and `libhwbinder-impl-internal`. Both old shared
library modules are deprecated empty carriers. A temporary experiment removed
only those two `DT_NEEDED` entries; imports and exports remained unchanged.
No implementation shim or replacement framework stack was introduced.

## Verification limit, not a demonstrated LOS24 libsync failure

The experiment used the current platform ELF checker with all checks enabled,
4096-byte alignment, public VNDK34 references for the Android C++/HIDL
dependencies, selected `clang-r596125` libc++, and stock liblog/libsync/bootstrap
bionic references. These were **offline references only**, not deployment inputs.

For both ABIs, strict symbol checking rejected exactly:

```text
sync_file_info@LIBSYNC
sync_file_info_free@LIBSYNC
sync_merge@LIBSYNC
sync_wait@LIBSYNC
```

The stock system libsync reference exports those names without symbol versions.
Crucially, current LOS24 `system/core/libsync/libsync.map.txt` declares the
required names in `LIBSYNC`. Thus the reference failure is **not proof that
final LOS24 libsync is incompatible**. Actual target dependency artifacts and
the complete candidate ELF checks have not been produced here.

The remaining work is dependency normalization and validation against final
target providers, including the LLNDK versioned libsync provider. This audit
neither establishes that a wider source stack is necessary nor claims runtime
or object-layout compatibility. It stops without adding a module or further
prebuilts. Temporary public candidate files were removed after verifying their
hashes; no proprietary BLA bytes were copied into this project.
